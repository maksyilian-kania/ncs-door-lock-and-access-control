## Objective

Verify application mailbox behavior when the real stack drives EXCHANGE over
a Fast session.

## Application-owned scope

- Exercise reads, writes, sets, permissions, commit, rollback, and lifecycle
  serialization through the existing mailbox backend.
- Verify snapshots and committed state at the application boundary.

## Non-goals and stack boundary

Do not parse EXCHANGE, orchestrate the secure channel, select counters, or
construct success/failure responses.

## Required verification

Run positive and failed Fast EXCHANGE host integration cases.

## Acceptance matrix

- Read, write, and set at start/end offsets under a matching Fast session.
- Read-only, write-only, out-of-bounds, wrong-length, and mixed-request
  failure cases leave committed mailbox state unchanged.
- Multiple write/set operations commit atomically only after complete
  success; field loss, authentication failure, and final Reader failure roll
  staged state back.
- Fast uses the same selected credential, mailbox permissions, snapshots,
  and transaction-result semantics already proven for Standard.
- Success, failure, timeout, and field loss each notify the application
  exactly once and return mailbox/session/temporary-handle counts to
  baseline.
- An independent Reader authenticates Fast EXCHANGE responses; secure-channel
  bytes, counters, and status sequencing remain stack-owned.

## Exit criteria

The complete positive/failure matrix preserves Standard mailbox semantics
and releases all application resources without application-side protocol
processing.

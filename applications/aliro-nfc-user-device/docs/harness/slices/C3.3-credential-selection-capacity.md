## Objective

Close the host-verifiable credential binding-capacity and duplicate-identifier
selection gaps identified by C1.4.

## Application-owned scope

- Verify at least 16 reader-group bindings on one Access Credential.
- Verify the development CLI can select every credential sharing one reader
  identifier.
- Cover persistence and deterministic behavior across update and deletion.

## Non-goals and stack boundary

Do not implement credential selection, Reader authentication, or protocol
policy in the application beyond the existing public lookup/preference
contract.

## Required verification

Run direct credential-store/CLI tests and real-stack Standard host integration
for the selected credential.

## Acceptance matrix

- Provision 16 distinct reader-group identifiers on one credential and
  authenticate through each binding using the same credential public key.
- Attempt the configured binding maximum plus one and prove deterministic,
  failure-atomic rejection without altering the accepted bindings.
- Provision at least two credentials with the same reader-group identifier;
  use the CLI to select each one and prove a later Standard transaction uses
  the selected credential.
- Cover preferred-set/get for unknown, deleted, updated, and unbound
  credentials with deterministic non-secret results.
- Preserve a valid preference across simulated reboot; deleting the selected
  credential leaves a documented deterministic state and allows another
  matching credential to be selected.
- Cite Aliro 1.0 §6.2 (pp.28–29) and Test Plan
  `NFC_UD_STANDARD_SIXTEEN_GROUPPIDENTIFIER_ONE_AC` (p.61).

## Exit criteria

Host evidence proves the 16-binding minimum and user selection of every
credential sharing an identifier without adding application protocol policy.

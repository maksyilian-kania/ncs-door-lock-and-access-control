## Objective

Qualify application storage and generic crypto backends on the target DK.

## Application-owned scope

- Run credential, `Kpersistent`, document, mailbox, and generic PSA backend
  tests on target.
- Verify reset and actual power-loss persistence.
- Confirm sensitive key objects remain non-exportable.

## Non-goals and stack boundary

Do not use target observations to patch or duplicate stack protocol logic.

## Required verification

Physical DK execution with exact application/stack revisions and durable
`evidence/C7.1.md`.

## Acceptance matrix

- Run credential, mailbox, document, persistent-key, and generic-PSA target
  suites from a clean flash; record exact case totals and configuration.
- Provision all stores, verify after software reset, then verify after actual
  power removal/restoration.
- Repeat representative power cuts before and after each durable commit
  boundary identified by C2.3/C3.2; recovered state is prior or new, never
  mixed.
- Replace/delete one credential and factory-reset multiple credentials;
  confirm associated documents, mailbox, and persistent keys do not reappear.
- Attempt PSA export/copy-to-exportable-policy of credential private keys and
  `Kpersistent`; inspect CLI, logs, crash output, and diagnostics for raw key
  material.
- Re-run after recovery/reset to prove storage capacity and PSA object slots
  are reusable with no orphan accumulation.

## Exit criteria

Every application backend survives required reset/power-loss cases and
protected keys remain non-exportable; `evidence/C7.1.md` maps every matrix
row to a result and artifact.

## Objective

Verify application state and resource ownership across Fast match, miss,
fallback, repetition, and teardown.

## Application-owned scope

- Exercise matching and missing persistent state, Standard fallback,
  repeated sessions, field loss, and teardown through the real stack.
- Assert application-observable persistent state and opaque-handle cleanup.

## Non-goals and stack boundary

Cover-cryptogram generation/content, fallback decisions, and wire-visible
privacy behavior are stack-owned. Record discrepancies; do not implement
them in the application.

## Required verification

Run host integration cases with backend resource/leak accounting.

## Acceptance matrix

- Matching state: Fast completes and releases every temporary handle while
  retaining the durable record.
- Missing credential, missing sub-identifier, and missing persistent key:
  application lookups expose the same failure shape and leave no resource.
- Two consecutive missing-state Fast requests return different externally
  observable cryptograms; content/privacy generation remains stack-owned
  (Aliro 1.0 §8.3.3.2.6, pp.69–70).
- A Reader that cannot match the cryptogram continues into Standard in the
  same NFC transaction and can complete successfully (Aliro 1.0
  §§8.1.1.2, 8.3.3.2.8, pp.51–54, 70–71).
- Field loss and timeout during match, miss, and fallback release temporary
  handles/session resources without deleting durable state.
- Repeat every path and assert stable application object, snapshot, timer,
  and transport counts.

## Exit criteria

Every match/miss/fallback/interruption path returns application resources to
baseline; wire/privacy discrepancies are precise stack blockers.

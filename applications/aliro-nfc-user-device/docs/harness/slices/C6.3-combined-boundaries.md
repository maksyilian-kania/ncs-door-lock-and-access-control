## Objective

Verify application boundaries when the corrected stack drives combined and
boundary Step-Up cases.

## Application-owned scope

- Supply Access and Revocation snapshots for combined, partial-match,
  no-match, maximum-size, chained, and one-byte-over-limit cases.
- Verify application bounds, snapshot lifetime, response-buffer lifetime,
  transaction notification, and cleanup.

## Non-goals and stack boundary

Document selection, deterministic CBOR, output ordering, chaining, response
capacity decisions, and failure sequencing are stack-owned.

## Required verification

Run the combined/boundary host matrix through the real stack.

## Acceptance matrix

- Request Access-only, Revocation-only, and both documents in one
  DeviceRequest; externally validate the exact available-document set.
- Cover partial match and no match. The no-data response omits the document
  field; selection and encoding remain stack-owned.
- Run zero/minimum, configured maximum, and one-byte-over-limit document and
  response-buffer cases, with both single and multiple GET RESPONSE rounds.
- Replace/delete documents while snapshots are open and prove returned bytes
  remain stable until release.
- Inject failure before/after each response-buffer handoff and between chained
  rounds; assert exactly one notification and full application cleanup.
- Verify deterministic CBOR, `aliro-a`/`aliro-r`, output ordering,
  SessionData protection, and error responses only through the corrected
  stack and independent Reader (Aliro 1.0 §§7.7, 8.4, pp.48, 88–92; Test
  Plan NFC_UD_STEPUP_AD_RD, p.66).

## Exit criteria

Every document combination and boundary has observable storage, buffer,
snapshot, notification, and cleanup assertions without application-owned
protocol behavior.

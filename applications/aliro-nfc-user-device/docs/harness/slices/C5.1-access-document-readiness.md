## Objective

Ensure the application can provision and supply a valid user-provided Access
Document through the public snapshot contract.

## Application-owned scope

- Provision a valid fixture through the development CLI.
- Verify committed storage and immutable `Document` retrieval.
- Cover absence, replacement, deletion, and snapshot lifetime.

## Non-goals and stack boundary

Do not construct, rewrite, interpret, or select content from stack-owned
Step-Up messages or document CBOR.

## Required verification

Run CLI-to-storage-to-public-interface host integration.

## Acceptance matrix

- Provision a valid user-supplied Access Document through the CLI and read
  back byte-for-byte identical content through the public `Document`
  snapshot contract.
- Cover absent document, replacement, clear, credential deletion, factory
  reset, and simulated reboot.
- Keep an already-open snapshot stable across replacement/deletion while a
  new snapshot observes the committed value.
- Cover zero/configured-maximum/one-over-maximum input and snapshot-capacity
  exhaustion without changing prior committed data.
- Abort and injected commit failure leave no staged bytes or leaked snapshot;
  the next valid provisioning transaction succeeds.
- Treat fixture content as opaque application data; no application code
  parses, rewrites, filters, or constructs Step-Up CBOR.

## Exit criteria

Every lifecycle and bound supplies either the exact committed opaque snapshot
or a deterministic error, with prior data and resource ownership preserved.

## Objective

Audit a stack revision that claims complete Revocation/combined Step-Up and
failure closeout before application integration continues.

## Entry gate

Do not start until the stack reports Revocation-only and combined responses,
truthful signaling, complete failure cleanup, and fixes for known
deterministic-CBOR/ordering defects.

## Application-owned scope

- Record and inspect the corrected stack revision/public headers.
- Adapt only for genuine public-contract changes.
- Re-run affected C1-C5 application regression tests.

## Non-goals and stack boundary

Do not fix stack implementation defects or add compatibility workarounds.

## Required verification

Contract diff, application build, and affected host suites.

## Acceptance matrix

- Record exact old/new stack revisions and map every changed public
  `Aliro::Interface::UserDevice` declaration to its application adapter and
  affected test.
- Confirm public APIs can represent Access-only, Revocation-only, combined,
  empty/no-match, multi-response, post-Step-Up EXCHANGE, and failure cleanup
  without application protocol decisions.
- Through a stack-owned test/probe, confirm truthful Access/Revocation
  signaling, Revocation-only and combined responses, deterministic CBOR,
  required response ordering, and complete failure teardown.
- Re-run every affected C1–C5 host configuration plus a clean DK build;
  record configuration/case totals and compiler warnings.
- Classify each failure as application contract misuse or exact stack defect.
  Do not adapt application code until the corresponding public-contract
  change is identified.
- If any entry-gate capability is absent or defective, create
  `../evidence/C6.1.md`, mark the path blocked, and stop C6.2/C6.3.

## Exit criteria

Every entry-gate capability is demonstrated at the exact stack revision and
all affected application regressions pass without a protocol workaround.

## Objective

Make application `Kpersistent` replacement and deletion recoverable across
settings/NVS and persistent PSA storage.

## Application-owned scope

- Define a durable transaction/recovery model.
- Recover interrupted replacement and deletion at boot.
- Destroy orphaned staged or retired persistent keys.
- Propagate cleanup failures rather than leaving metadata/key divergence.

## Non-goals and stack boundary

Do not alter the stack's key derivation, lookup key, or protocol commit
timing.

## Required verification

Test every recovery state directly with fake persistence and PSA ownership,
including repeated boot recovery.

## Acceptance matrix

- Document every durable replacement/deletion state and its authoritative
  metadata and PSA objects.
- Recover interruption before and after each metadata commit, key ownership
  transfer, old-key retirement, credential deletion, and factory reset.
- Preserve the previous committed record when replacement has not committed;
  expose only the new record after it has committed.
- Repeated boot recovery reaches the same stable state without creating,
  losing, or double-destroying a PSA object.
- Cleanup failure is returned or retained as recoverable state; it is never
  silently converted into metadata/key divergence.
- Credential deletion and reset remove their associated persistent-key
  records, closing the C1.4 cleanup assignment.

## Exit criteria

Every persistence transition has a deterministic, idempotent recovery rule
and direct test, with no unowned PSA object after successful recovery.

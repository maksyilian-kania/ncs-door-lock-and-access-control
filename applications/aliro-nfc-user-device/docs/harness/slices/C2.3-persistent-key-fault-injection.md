## Objective

Prove the application persistent-key recovery model at every failure
boundary.

## Application-owned scope

- Inject failure before and after every metadata and PSA transition.
- Verify preservation of prior committed state or deterministic recovery.
- Verify recovery idempotence and PSA-object leak freedom.
- Record the fault matrix as durable evidence.

## Non-goals and stack boundary

Do not inject into or change stack key derivation/protocol sequencing.

## Required verification

Run the complete backend fault matrix on the host. Target reset/power-loss
qualification remains C7.1.

## Acceptance matrix

- Inject failure immediately before and after every durable metadata write,
  delete, PSA ownership transfer, copy, and destroy operation.
- Cover insert, replacement, single delete, credential-wide delete, factory
  reset, and boot recovery.
- For every row, assert the visible record, surviving PSA objects, returned
  error, and next-boot recovery result.
- Run recovery twice after each injected failure to prove idempotence.
- End every row with either the prior or new committed state—never a mixed
  record—and with no unexplained PSA object.
- Record operation, injection point, pre-state, immediate state, recovered
  state, and object-count result in `../evidence/C2.3.md`.

## Exit criteria

Every enumerated persistence transition has before/after fault coverage and
the durable matrix contains no unexplained or leaking state.

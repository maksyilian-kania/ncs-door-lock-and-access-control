## Objective

Cover application Access/Revocation Document storage and immutable snapshot
behavior independently of Step-Up.

## Application-owned scope

- Test independent Access and Revocation persistence/retrieval.
- Test immutable snapshots, concurrent capacity, overflow-safe reads,
  deletion, and reset.
- Validate application capacity configuration against the public contract.

## Non-goals and stack boundary

Do not parse DeviceRequest/DeviceResponse CBOR or select document elements.

## Required verification

Run direct document-store and public-interface tests with persistence fakes.

## Acceptance matrix

- Independently create, retrieve, replace, delete, and reset Access and
  Revocation Documents for multiple credentials.
- Preserve exact provisioned bytes and document type; never reinterpret or
  normalize document CBOR.
- Keep an open snapshot immutable across replacement/deletion while a newly
  opened snapshot observes the committed state.
- Cover zero length, configured maximum, one over maximum, short destination,
  offset/length overflow, invalid handle, and snapshot-table exhaustion.
- Reinitialize from persisted data and prove committed documents survive a
  simulated reboot while deleted/reset documents do not reappear.
- Release every snapshot on success, failure, and reset; assert capacity is
  reusable and no backing allocation remains owned.

## Exit criteria

Access and Revocation storage, reboot, snapshot isolation, and every
configured bound have direct assertions with no leaked snapshot.

## Objective

Verify generic application PSA and `PersistentKey` operations exercised by
the stack's Fast flow.

## Application-owned scope

- Test opaque import, derivation-input handle use, lookup, copy, and
  destruction operations exposed by the current public contract.
- Verify failure outputs and resource ownership.

## Non-goals and stack boundary

Do not construct Fast salts, KDF inputs, cryptograms, direction keys,
counters, or Fast protocol state.

## Required verification

Run direct generic crypto and persistent-key backend tests.

## Acceptance matrix

- Map every Fast-reachable public stack call to one application definition
  and a direct test; absent calls are exact stack-contract blockers.
- Cover opaque persistent-key lookup hit/miss, temporary-handle mint/copy,
  generic derivation input use, and destruction in the order permitted by
  the public headers.
- Assert deterministic outputs and unchanged durable state for invalid
  handles, wrong attributes, capacity exhaustion, PSA failure, and repeated
  cleanup.
- Account for all temporary and persistent PSA objects after every success
  and injected failure.
- Confirm application code/tests neither assemble Fast salts nor inspect,
  export, compare, or log raw `Kpersistent` or derived session-key bytes.

## Exit criteria

Every application backend operation required by the current Fast contract is
mapped and directly tested for success, failure outputs, and resource
ownership with no protocol construction in application code.

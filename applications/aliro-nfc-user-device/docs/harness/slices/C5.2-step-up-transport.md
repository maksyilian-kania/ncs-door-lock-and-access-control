## Objective

Verify application NFC transport behavior during same-session Access-only
Step-Up driven by the real stack.

## Application-owned scope

- Deliver ENVELOPE and GET RESPONSE APDUs without deactivation.
- Verify response-buffer lifetime and uninterrupted session delivery.
- Supply the Access Document snapshot through the public contract.

## Non-goals and stack boundary

Do not implement chaining, SessionData, CBOR, key/counter handling, document
selection, or response construction.

## Required verification

Run Access-only Step-Up host integration through the real transport/stack
boundary.

## Acceptance matrix

- Complete Standard then Access-only Step-Up without field-off, transport
  restart, or intentional protocol deactivation in between.
- Deliver ENVELOPE and every required GET RESPONSE APDU through the existing
  worker in order; cover a one-response result and a result requiring
  multiple GET RESPONSE rounds.
- Hold the application response buffer and Access Document snapshot until
  the stack/transport contract releases them; replacement during the open
  snapshot cannot alter returned bytes.
- An independent Reader decrypts SessionData with the Standard-derived
  StepUpSK and validates the requested Access Document flow, proving the
  P1-025 StepUpSK clause at the boundary.
- Cover absent document, no matching requested element, transport send
  failure, field loss, and timeout with deterministic application cleanup.
- DeviceRequest parsing, DeviceResponse/SessionData construction,
  deterministic CBOR, keys/counters, and response segmentation remain
  stack-owned (Aliro 1.0 §§8.4.1–8.4.4, pp.88–92).

## Exit criteria

Single- and multi-response Access-only Step-Up satisfy transport, snapshot,
buffer-lifetime, and cleanup assertions; protocol discrepancies are exact
stack blockers.

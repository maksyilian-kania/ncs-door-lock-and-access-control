## Objective

Collect physical Reader/conformance evidence for selected Standard, Fast,
mailbox, chaining, negative, RF-continuity, and fallback behavior.

## Application-owned scope

- Build/flash a release-like application configuration.
- Run the applicable external Reader tests.
- Capture application transport/backend observations and exact revisions.

## Non-goals and stack boundary

Record protocol failures as stack defects unless an application public-
contract violation is demonstrated. Do not implement a workaround.

## Required verification

Physical DK and Reader/conformance harness run with durable
`evidence/C7.2.md`.

## Acceptance matrix

- DK/antenna boot, NFC-A/ISO-DEP listen mode, SELECT, virtual-UART CLI at
  115200 8N1, button/indicator, and applicable target timing.
- `NFC_UD_STANDARD_NO_CERT`, certificate-in-LOAD-CERT and
  certificate-in-AUTH1 with chaining, and AUTH0 response chaining.
- Sixteen reader-group identifiers on one credential and user selection
  between credentials sharing an identifier (P1-009/P1-010).
- Applicable AUTH0/AUTH1/EXCHANGE negative, extra-tag, wrong-value,
  wrong-P1/P2, incomplete-chaining, bounds, permission, and CONTROL FLOW
  cases listed in Requirements.pdf §12.
- `NFC_UD_FAST`, consecutive unmatched-Fast cryptograms, Standard fallback,
  Fast EXCHANGE, field loss, and repeated transactions.
- For every case, record test ID, PICS/applicability, revisions, result,
  application observations, and exact owner of any failure; do not replace
  an applicable conformance case with a host test.

## Exit criteria

Every applicable selected Standard/Fast test ID and target-only project
requirement has a recorded pass or precise reproducible blocker in
`evidence/C7.2.md`.

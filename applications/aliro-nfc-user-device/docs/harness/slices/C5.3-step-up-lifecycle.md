## Objective

Verify application lifecycle/resource behavior around stack-driven Step-Up
rounds, interruption, and completion.

## Application-owned scope

- Exercise repeated rounds, post-Step-Up EXCHANGE, interruption, timeout,
  field loss, and recovery.
- Verify timers, transport, snapshots, transaction notification, and
  application resource cleanup.

## Non-goals and stack boundary

Step-Up failure classification, key/counter selection, secure-channel
handling, and wire responses are stack-owned.

## Required verification

Run lifecycle/failure host integration with application resource accounting.

## Acceptance matrix

- Complete one and repeated Access-only Step-Up rounds, followed by successful
  post-Step-Up EXCHANGE authenticated by an independent Reader.
- Interrupt during ENVELOPE, between GET RESPONSE rounds, after the final
  Step-Up response, and during post-Step-Up EXCHANGE.
- Cover field loss, watchdog timeout, transport-send failure, malformed
  stack-rejected input, and final Reader success/failure.
- For every path, assert exactly one transaction notification with the
  expected application-visible outcome and no notification after teardown.
- Release document snapshots, response buffers, timers, transport/session
  state, and temporary PSA handles; durable documents/credentials remain
  available to a subsequent clean transaction.
- Failure classification, StepUpSKDevice/counter use, error status, and
  failure sequencing remain stack-owned.

## Exit criteria

Every completion/interruption point returns all application resources to
baseline and a new transaction succeeds; protocol discrepancies are exact
stack blockers.

## Objective

Define and test normal, boundary, and ownership behavior of the application
`Kpersistent` backend independently of protocol flow.

## Application-owned scope

- Test lookup, replacement, capacity, deletion, credential deletion, and
  factory reset.
- Define deterministic failure outputs.
- Verify ownership and cleanup of temporary and persistent PSA handles.

## Non-goals and stack boundary

Do not derive `Kpersistent`, construct protocol salts, or decide when the
stack creates or consumes a record.

## Required verification

Run direct backend tests with an application-owned in-memory persistence/PSA
fake and leak accounting.

## Acceptance matrix

- Lookup hit and miss for exact credential/sub-identifier pairs, including
  deterministic output initialization on failure.
- First insert, same-pair replacement, per-credential/global capacity, and
  one-over-capacity rejection without changing committed state.
- Single-record deletion, credential-wide deletion, and factory reset,
  including unknown/already-removed records.
- Success and failure ownership of every input, persisted, copied, and
  temporary PSA handle, with zero leaked or double-destroyed objects.
- No raw `Kpersistent` bytes in application output, logs, diagnostics, or
  test failure text.

## Exit criteria

Every public backend operation has normal, boundary, failure-output, and
handle-ownership assertions; the final fake-PSA object count is zero.

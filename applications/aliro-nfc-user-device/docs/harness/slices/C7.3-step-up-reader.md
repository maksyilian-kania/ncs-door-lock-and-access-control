## Objective

Collect physical Reader/conformance evidence for the selected NFC Step-Up
profile.

## Application-owned scope

- Run Access-only, Revocation-only, combined, chained, boundary, negative,
  interruption, and post-Step-Up EXCHANGE cases.
- Measure applicable timing and resource bounds in a release-like build.
- Capture application transport/backend behavior and exact revisions.

## Non-goals and stack boundary

Protocol defects remain stack-owned and must not be patched in the
application.

## Required verification

Physical DK and Reader/conformance harness run with durable
`evidence/C7.3.md`.

## Acceptance matrix

- Run `NFC_UD_STEPUP_AD`, `NFC_UD_STEPUP_RD`, and
  `NFC_UD_STEPUP_AD_RD` from Standard in the same physical NFC session.
- Exercise single-response and multiple-GET-RESPONSE transfers, maximum
  selected size, one-byte-over-limit, partial match, and no-data response.
- Run post-Step-Up EXCHANGE success/failure plus interruption at ENVELOPE,
  between GET RESPONSE rounds, after response, timeout, and field loss.
- Freeze the exact external-harness version and inventory before testing.
  Run every applicable selected User Device Step-Up case in that inventory,
  plus the interruption/fault rows defined by C5.3/C6.3; excluded Step-Up AID
  selection remains excluded.
- Confirm a clean transaction succeeds after each failure and application
  snapshot/buffer/timer/resource counts return to baseline.
- For every case, record test ID, PICS/applicability, revisions, result,
  Reader artifact, application observation, and exact failure owner.

## Exit criteria

Every applicable selected Step-Up test ID and interruption/boundary row has a
recorded pass or precise reproducible blocker in `evidence/C7.3.md`.

## Objective

Make application document provisioning deterministic and failure-atomic.

## Application-owned scope

- Reject malformed application provisioning encoding, inconsistent
  metadata, and oversized input.
- Preserve previously committed documents on every rejected input/failure.
- Cover create, update, clear, delete, and reset paths through the
  development provisioning surface.

## Non-goals and stack boundary

Do not validate stack-owned DeviceRequest/DeviceResponse CBOR or reconstruct
Step-Up responses.

## Required verification

Run provisioning boundary and failure tests on host. Target persistence
remains C7.1.

## Acceptance matrix

- Provision Access-only, Revocation-only, both documents, and neither through
  create and update transactions; inspect exact committed metadata/bytes.
- Cover clear, credential delete, and factory reset. Delete/reset must also
  erase the credential's mailbox, closing the C1.4 cascade assignment;
  persistent-key cleanup remains owned by C2.2.
- Reject malformed CLI encoding, wrong declared length/type, inconsistent
  metadata, duplicate fields, configured maximum plus one, and setters used
  outside an open transaction.
- Inject each application persistence/commit failure and prove the previous
  credential, documents, and mailbox remain unchanged.
- Abort and failed commit leave no staged document or open snapshot; a later
  valid transaction succeeds.
- Return deterministic, non-secret CLI results for every accepted and
  rejected case.

## Exit criteria

Every create/update/clear/delete/reset boundary has a deterministic result;
all rejected or failed transactions preserve the prior committed state.
